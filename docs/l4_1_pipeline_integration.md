## 1. Scope

L4.1 transforms the L0–L4 evidence chain from a set of isolated, individually-tested
modules into a single end-to-end pipeline that preserves candidate identity and
emits truthful provenance.

**What L4.1 changed**:

- Added `l4_1_orchestrator.py` — a new orchestrator that wires the existing
  v0.1 / v1.0 / v1.1 / v1.2.x / L4 modules end-to-end.
- Added `test_l4_1_pipeline_integration.py` — 26 integration tests (A–Z + extras)
  verifying lineage, provenance, fail-closed, and security.
- Regenerated canonical `data/arbitrage_evidence_l4.json` from the actual pipeline
  output, with honest provenance (no relabeling of mock as live).

**What L4.1 deliberately did NOT change**:

- No modification to `candidate_discovery.py`, `run_pipeline.py`,
  `schedule_intelligence.py`, `price_intelligence.py`, `kiwi_price_provider.py`,
  `live_schedule_provider.py`, `fx_provider.py`, `passenger_parity.py`,
  `baseline_canonicalization.py`, `comparison_engine.py`, `arbitrage_detection.py`,
  `eval_flight_yc.py` (Jev), or `flight_dashboard.py`.
- No L5 implementation.
- No VERIFIED_OPPORTUNITY emission.
- No new providers, credentials, or scoring logic.

## 2. Previous Audit Defects

### 2.1 Pipeline disconnected (BEFORE → AFTER)

**BEFORE** (per L0–L4 audit):
- `run_pipeline.py` orchestrated only Discovery → Jev.
- v1.0 / v1.1 / v1.2.x / L4 stages were exercised individually with synthetic
  fixtures, never chained.
- `arbitrage_evidence_l4.json` was generated by `_l4_gen_fixtures.py`,
  bypassing the pipeline.

**AFTER**:
- `l4_1_orchestrator.run_l41_pipeline(mission_path)` runs 9 stages:
  Mission → Credential Check → Discovery (v0.1) → Schedule (v1.0) →
  Price (v1.1/v1.2.0) → Live Schedule (v1.2.1) → FX (v1.2.2) →
  Baseline/Parity/Comparison/L4 (per pair).
- Each stage invokes the existing module via in-process Python API or subprocess
  CLI; no module logic was duplicated.

**STATUS**: ✅ FIXED.

### 2.2 Candidate ID broken (BEFORE → AFTER)

**BEFORE**:
- Discovery produces `AUTO-multi_ticket-TPE-KUL-MAD` etc.
- The L4 canonical record had `candidate_id="A"` — synthetic, untraceable.
- Each v1.x evidence artifact (price, fx, parity, baseline, comparison, L4) used
  different identifiers (`TEST-A`, `c1`, `A`).

**AFTER**:
- Discovery emits `AUTO-*` ids (unchanged).
- The orchestrator propagates the SAME `candidate_id` through every stage.
- The canonical L4 record is `candidate_id="AUTO-L41-multi_ticket-TPE-KUL-MAD"`
  — a real discovery-produced id.

**STATUS**: ✅ FIXED.

### 2.3 Synthetic canonical provenance (BEFORE → AFTER)

**BEFORE**:
- `arbitrage_evidence_l4.json` was labeled `provider="duffel"`,
  `provider_mode="live"`, but the underlying evidence was synthetic.
- `verification_status` claimed LIVE for a record with no real Duffel
  request history.

**AFTER**:
- Canonical record now reads:
  ```
  price_evidence_refs.candidate.provider = mock_duffel
  price_evidence_refs.candidate.provider_mode = mock
  price_evidence_refs.candidate.verification_status = LIVE
  ```
  (Mock provider with mock mode; LIVE comes from v1.2.1 mock schedule,
  not Duffel.)
- The v1.0 schedule_enrichment is OpenFlights DATABASE (not LIVE).
- The FX is Frankfurter LIVE (real smoke request).

**STATUS**: ✅ FIXED.

### 2.4 Field loss (deferred to L5)

**STATUS**: PARTIAL — see §8 for the full list of deferred fields.

L4.1 does NOT solve all field losses (per spec PART 13). The orchestrator
preserves any fields already available in candidate / evidence dicts but does
not redesign the upstream schemas.

## 3. Actual End-to-End Architecture

```
[User] mission.json
   ↓
l4_1_orchestrator.run_l41_pipeline(mission_path)
   ↓
[Stage 1] Mission load → mission dict
   ↓
[Stage 2] Credential check
   ↓  fail-closed if provider=duffel/kiwi with provider_mode=live
      and no env credential
[Stage 3] candidate_discovery.generate_candidates(mission)
   ↓  in-process Python import
   → list of candidates with AUTO-* ids
[Stage 4] schedule_intelligence.enrich_candidates(candidates)
   ↓  in-process; enrich_candidates returns (enriched, traces, summary)
   → list of enriched candidates (OpenFlights DATABASE evidence)
[Stage 5] Write candidates to l4_1_workdir/candidates_for_price.json
   ↓
   subprocess: price_intelligence.py <cand.json> --max-searches N --smoke-test ...
   ↓  Read output JSON
   → list of PriceEvidence records keyed by candidate_id
   (provider_mode = "live" if DUFFEL creds, "mock" otherwise)
[Stage 6] subprocess: live_schedule_provider.py <cand.json> --schedule-provider mock_duffel ...
   ↓  Read output JSON
   → list of ScheduleEvidence records keyed by candidate_id
   (provider = mock_duffel, provider_mode = mock, verification_status = LIVE)
[Stage 7] subprocess: fx_provider.py --fx-provider frankfurter --base TWD --quote EUR --smoke-test ...
   ↓  Read output JSON
   → single FXEvidence (or None)
[Stage 8] Pair LIVE candidates by origin/destination.
   For each pair (A, B):
     a. passenger_parity.evaluate_passenger_parity(a_norm, b_norm)
        → ParityEvidence
     b. baseline_canonicalization.canonicalize_for_candidate(mission, A)
        → CanonicalBaseline
     c. comparison_engine.build_comparison_evidence(A, B, fx, baseline, "EUR")
        → ComparisonEvidence
     d. arbitrage_detection.build_arbitrage_evidence(A, baseline, comparison, ...)
        → ArbitrageEvidence (with REAL candidate_id)
[Stage 9] Write all artifacts; canonical = first arbitrage sorted by candidate_id
   ↓
[l4_1_run_trace.json]
```

**Modules and their responsibility**:
| Stage | Module | In-process or CLI |
|-------|--------|-------------------|
| 3 Discovery | candidate_discovery.py | in-process |
| 4 Schedule | schedule_intelligence.py | in-process |
| 5 Price | price_intelligence.py | subprocess CLI |
| 6 Live Schedule | live_schedule_provider.py | subprocess CLI |
| 7 FX | fx_provider.py | subprocess CLI |
| 8a Parity | passenger_parity.py | in-process |
| 8b Baseline | baseline_canonicalization.py | in-process |
| 8c Comparison | comparison_engine.py | in-process |
| 8d L4 | arbitrage_detection.py | in-process |

## 6. Canonical Artifact Integrity

The canonical `data/arbitrage_evidence_l4.json` is generated by:
1. `candidate_discovery.generate_candidates(mission)` — produces AUTO-* ids.
2. `schedule_intelligence.enrich_candidates(candidates)` — preserves id.
3. `price_intelligence.py` subprocess with the same candidates file.
4. `live_schedule_provider.py` subprocess with the same candidates file.
5. `fx_provider.py` subprocess for Frankfurter FX.
6. `passenger_parity.evaluate_passenger_parity` for each pair.
7. `baseline_canonicalization.canonicalize_for_candidate` per candidate.
8. `comparison_engine.build_comparison_evidence` for each pair.
9. `arbitrage_detection.build_arbitrage_evidence` for each pair.
10. Pick first arbitrage (sorted by candidate_id) as canonical.

The previous `_l4_gen_fixtures.py` synthetic fixture generator is no longer the
source of the canonical artifact (the file is overwritten by `l4_1_orchestrator`).

**Test J** verifies this: `arb.candidate_id` MUST be in the discovery output,
and MUST NOT be `"A"` or `"TEST-A"`.

## 9. L4 Semantic Regression

L4 semantics are **unchanged**. The orchestrator invokes
`arbitrage_detection.build_arbitrage_evidence` exactly as before. The
following boundaries continue to hold:

- `PRICE DIFFERENCE != ARBITRAGE` ✓
- `HARD_COMPARABLE != ARBITRAGE` ✓
- `CHEAPER != ARBITRAGE` ✓
- `PROVIDER DISAGREEMENT != ERROR` ✓
- `OUTER-PORT != AUTOMATIC ARBITRAGE` ✓
- `POSITIONING != AUTOMATIC ARBITRAGE` ✓
- `JEV SURVIVOR != ARBITRAGE` ✓
- `information_priority_score != arbitrage_score` ✓
- `LIVE != BOOKABLE` ✓
- `VERIFIED != BOOKABLE` ✓

The existing L4 adversarial / negative test suite (50 tests in
`test_arbitrage_detection_l4.py`) was re-run by test_X of the integration
suite and PASSED.

No new arbitrage states, scores, rankings, or thresholds were introduced.
