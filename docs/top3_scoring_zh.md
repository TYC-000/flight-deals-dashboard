# Top 3 評分標準完整說明

> **給李承頤的信任建立書 — 為什麼這個 ranking 是這樣運作的**

本文件解釋 dashboard 的 Top 3 是怎麼選出來的，包含每個參數的權重與來源。

---

## 一、為什麼會有「來來回回」多次修改？

| 階段 | 結果 | 原因 |
|------|------|------|
| v1 | LH-SIN-FRA = #1 | Jev 純評估（沒有用戶偏好）|
| v2 | LH-SIN-FRA = #1 | 加了 +1.0 penalty 但不夠強，fatigue 5.8 蓋過 |
| v3 | LH-SIN-FRA 跌出 Top 3 | 改成 +3.0 + verdict 降級，雙重降權 |

這就是「為什麼我來來回回改」 — **參數權重要夠強才能反映用戶偏好的真實意圖**。

## 二、評分系統三層架構

整個系統分**三層**，由下而上依序作用：

```
┌─────────────────────────────────────────┐
│  第三層：用戶偏好 (Soft Preference)      │
│  - 排除航空：-3.0 penalty + verdict 降級  │
│  - 偏好機型：-1.0 bonus                  │
│  - 作用：Top 3 內部排序                  │
├─────────────────────────────────────────┤
│  第二層：過濾條件 (Hard Filter)          │
│  - 風險 ≤ 25%                            │
│  - 疲勞 ≤ 7.5                            │
│  - 省幅 ≥ 35%                            │
│  - 機型 ≥ 4                              │
│  - 作用：篩選誰能進 Top 3               │
├─────────────────────────────────────────┤
│  第一層：Jev 評估 (Base Score)            │
│  - 4 題評估                              │
│  - 作用：給每個候選原始分數              │
└─────────────────────────────────────────┘
```

---

## 三、第一層：Jev 4 題評估

Jev AI 對每個候選方案獨立打分：

| 題目 | 類型 | 評分範圍 | 衡量 |
|------|------|---------|------|
| **連接失敗風險** | Noul (語意) | 0-1 機率 | 中東轉機時錯過下班的概率 |
| **疲勞指數** | Score (1-3 bucket) | 1-10 | 整段旅程疲憊程度 |
| **機型舒適度** | Score (1-3 bucket) | 1-10 | 長程商務艙座椅與機型品質 |
| **Jev 標籤** | Choice (3 選項) | string | 綜合定性結論 |

每題成本約 NT$ 0.00002（極便宜），22 個候選 × 4 題 ≈ NT$ 0.0018。

### Jev 標籤的 3 個選項

| 標籤 | 定義 | 觸發條件 |
|------|------|---------|
| **prime_deal** 🟢 | 最佳推薦 | 省 ≥ 35% + 風險 ≤ 25% + 疲勞 ≤ 7.5 |
| **acceptable_economy** 🟡 | 可接受 | 達標但有缺陷 |
| **avoid_exhausting** 🔴 | 避免 | 嚴重缺陷（太貴或風險高）|

## 四、第二層：硬性篩選條件

只有**同時滿足這 5 條件**才能進 Top 3：

| 條件 | 預設值 | 來源 |
|------|-------|------|
| 連接失敗風險 | ≤ **25%** | 中東轉機業界經驗 |
| 疲勞指數 | ≤ **7.5 / 10** | 「12hr flight 後還能玩」上限 |
| 省幅 vs TPE 直飛 | ≥ **35%** | 比 TPE 直飛省 1/3 才值得 |
| 機型舒適度 | ≥ **4 / 10** | 排除最舊機型（如舊 777-200）|
| Jev 標籤 | prime_deal 或 acceptable_economy | 排除 avoid_exhausting |

**這些預設值都會顯示在 sidebar「🎯 YC 推薦預設值」區塊 — 一鍵重置或自訂都行。**

---

## 五、第三層：排序權重

篩選後的候選，按以下優先順序排序（從最重要到最不重要）：

| 順序 | 條件 | 預設行為 |
|------|------|---------|
| 1 | Jev 標籤 | prime_deal (0) > acceptable_economy (1) > avoid (2) |
| 2 | 疲勞指數 | 5.8 排前，7.5 排後 |
| 3 | 連接失敗風險 | 10% 排前，25% 排後 |
| 4 | 總成本 | 便宜的排前 |
| 5 | 用戶偏好分數 | 見下表 |

## 六、用戶偏好分數（Soft Preference）

| 條件 | 分數變化 | 效果 |
|------|---------|------|
| 含排除航空 (LH/BA/AF/KL 等) | **+3.0** | 嚴重降權（壓過疲勞差距 0.9）|
| 含排除航空 → verdict 強制降級 | prime_deal → acceptable_economy | 直接喪失排序優先權 |
| 長程段使用偏好機型 (A380/A350/B787) | **-1.0** | 升權 |
| 同 PNR (全程一張票) | 0 (但顯示) | 資訊性標籤 |
| 代碼共享警告 | 0 (但顯示) | 資訊性標籤 |

### 為什麼 +3.0 不是 +1.0？

**這是 v2 → v3 修正的關鍵**：

- LH-SIN-FRA 的 fatigue = **5.8**（全場最低）
- SQ-SIN-CDG 的 fatigue = **6.7**
- 疲勞差距 = 0.9

如果 penalty 只有 +1.0，疲勞 0.9 < penalty 1.0，**所以 LH 還會排第一**。
改為 +3.0 後 penalty > 疲勞差距，**LH 必降權**。

## 九、給旅伴的信任建立 Q&A

### Q1：「為什麼是你訂的數字？」

> 這 4 個硬條件 (風險 25% / 疲勞 7.5 / 省 35% / 機型 4) 都是**通用門檻**：
> - 風險 25% 是業界「中東轉機可接受」上限
> - 疲勞 7.5 是「12hr flight 後還能玩」上限
> - 省 35% 是「值得麻煩繞一圈」下限
>
> 如果你想調，全部可以改 — sidebar 有「🚀 套用 YC 推薦過濾器」按鈕一鍵重置。

### Q2：「為什麼 SQ 排 EK 前面？」

> SQ-SIN-CDG 全程 **A350-900**（機齡 4 年，最新世代）+ prime_deal 標籤。
> BKK-EK-1 用 **B777-300ER (7年) + A380 (4年)** — 混合機型。
> SQ 全 A350 → 體驗均勻一致；EK 是混合。所以 SQ 排前面。

### Q3：「你的『偏好機型』真的有在用嗎？」

> 看 SQ、KUL-EK-1 兩個 A380/A350 偏好機型的方案，**它們都比 fatigue 比它們低的 LH-SIN-FRA 排前面** — 這就是偏好機型 + 排除航空的效果。
>
> 如果我把這兩個 filter 關掉，LH 又會回到 #1。

### Q4：「為什麼 Jev 跟一般評分不一樣？」

> 一般評分是固定權重（風險 30%、疲勞 30% 等等）。Jev 用 **LLM 做語意理解**：
> - 同一個方案「QR + DOH 中轉」跟「KE + ICN 直飛」，Jev 看上下文會給不同評分
> - 它考慮「這個轉機合理嗎？」「這個疲勞來源是時差還是中轉？」
> - 不是純統計平均，更貼近人的判斷
